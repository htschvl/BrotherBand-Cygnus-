### 4f. Enhanced error handling & observability (using Huma features)

Leverage Huma’s error‑handling capabilities to ensure every error is caught, logged with context, and returned consistently.

#### 4f.i. Use Huma’s native error model

Replace all manual `huma.Error` calls with a **centralised error mapper** that converts domain errors (from use cases) into Huma errors.  
Create a file `internal/adapter/http/error_mapper.go`:

- Define a `DomainError` interface that exposes `HTTPStatus() int`, `Code() string`, `Message() string`, `Details() any`.
- Implement this interface for all sentinel errors in `domain/` and for `ValidationError`.
- Write a function `MapToHumaError(err error) error` that:
  - If `err` is `nil` → return `nil`
  - If `err` is already a `*huma.ErrorModel` → return it
  - If `err` implements `DomainError` → return `huma.NewError(err.HTTPStatus(), err.Message(), map[string]any{"code": err.Code(), "details": err.Details()})`
  - For any unknown error → log with stack and return `huma.Error500InternalServerError("internal server error")`

#### 4f.ii. Add a global Huma error hook

After creating `humaApi`, attach an error hook that logs every error returned from any operation:

```go
humaApi.UseErrorHook(func(ctx context.Context, err error) {
    if err == nil { return }
    log := zerolog.Ctx(ctx)
    // Extract request_id from context
    reqID, _ := ctx.Value("request_id").(string)
    if humaErr, ok := err.(*huma.ErrorModel); ok {
        if humaErr.Status >= 500 {
            log.Error().Str("request_id", reqID).Stack().Err(err).Msg("internal server error")
        } else {
            log.Warn().Str("request_id", reqID).Err(err).Msg("client error")
        }
    } else {
        log.Error().Str("request_id", reqID).Stack().Err(err).Msg("unhandled error")
    }
})
```

This guarantees **every** error that leaves a Huma operation is logged, regardless of whether the handler logs it.
