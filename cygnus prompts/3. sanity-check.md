# Final Sanity Check – BrotherBand Cygnus Migration

All migration phases are complete. Now run this final verification checklist.

## Setup

1. Start the server: `make run` (or `make dev` if you prefer)
2. Ensure PostgreSQL and R2 (or MinIO for local dev) are running.

## Verification checklist

Run through each item and report ✅ or ❌.

### Logging
- [ ] Colored, timestamped logs appear in terminal on every request.
- [ ] Each log line includes **two timestamp fields**: human‑readable UTC (e.g., `2026-05-19 14:30:45.123`) and Unix epoch seconds (e.g., `"timestamp_unix": 1747661445`).
- [ ] Logs include `request_id`, `method`, `path`, `status`, `duration_ms`, `remote_ip`, `user_agent`, `response_size`.
- [ ] A slow request (>100ms) is logged at `WARN` level (or at least includes a noticeable field).

### OpenAPI specs
- [ ] `curl http://localhost:3000/openapi.json` returns valid OpenAPI 3.1 JSON.
- [ ] `curl http://localhost:3000/openapi.yaml` returns valid OpenAPI 3.1 YAML.
- [ ] `curl http://localhost:3000/openapi/tags/users.yaml` returns a spec containing **only** user‑related endpoints.
- [ ] `curl http://localhost:3000/openapi/tags/brotherbands.yaml` works similarly.
- [ ] `curl http://localhost:3000/openapi/tags/messages.yaml` works similarly.

### Scalar UI
- [ ] `http://localhost:3000/docs` loads the monolithic spec in Scalar UI (CDN, no local JS files).
- [ ] `http://localhost:3000/docs/users` loads the filtered user spec.
- [ ] `http://localhost:3000/docs/bands` loads the filtered brotherbands spec.
- [ ] `http://localhost:3000/docs/messages` loads the filtered messages spec.
- [ ] The UI has a modern theme, dark mode works, “Try it out” button sends requests to `http://localhost:3000` (or your configured server URL).

### Middleware & error handling
- [ ] Send a request without a `bb_session` cookie to an authenticated endpoint → returns 401 with JSON error containing `requestId`.
- [ ] Send a valid request but with a wrong/missing `X-CSRF-Token` → 403 with `requestId`.
- [ ] Force a panic inside a handler (temporarily add `panic("test")`) → returns 500 JSON with `requestId`, and the terminal log shows a full stack trace with zerolog.
- [ ] CORS preflight OPTIONS request returns 204 with correct `Access-Control-Allow-Origin`.

### Production enhancements
- [ ] `make dev` starts the server with `air`. Change a `.go` file – the server restarts automatically.
- [ ] Press Ctrl+C while the server is running → server waits up to 30 seconds for existing requests, then exits cleanly (no “context canceled” errors in logs).
- [ ] Send a request that exceeds the rate limit (e.g., 21 requests in 1 minute to `/v1/media/upload-url`) → the rate‑limited requests receive a 429 response, a Prometheus counter `rate_limit_hits_total` increments (check `/metrics`), and a `WARN` log appears with `request_id`, `path`, `remote_ip`.
- [ ] `GET /readyz` returns 200 when Postgres and R2 are reachable. Stop Postgres (or R2) – `/readyz` returns 503. `GET /healthz` always returns 200 (liveness).

### Tests & benchmarks
- [ ] `make test` passes all tests (unit + integration). No races.
- [ ] `go test -bench=. ./...` runs without errors. Document the results in `/docs/benchmark_results.md` (or similar). The README includes a summary of those results.

### Documentation
- [ ] `README.md` no longer mentions `slog`, `split-openapi.py`, `swaggo`, or `scalar-go` (except maybe in the "Removed" section).
- [ ] README includes new sections: OpenAPI docs (`/docs`, `/docs/users`, etc.), hot reload (`make dev`), benchmark results overview.
- [ ] `/docs` folder (any `.md` files) have been updated to reflect the new architecture (Huma, zerolog, Scalar).

## Final report

After completing the checklist, produce a summary:

- **Passed**: list of all items that succeeded.
- **Failed**: any item that failed (with details).
- **Recommendations**: if anything needs manual follow‑up.

If all items pass, the migration is successful.
